# 专业有声书生产流程调研：照书念 vs 先改剧本？

调研日期：2026-08-30。纯研究，未改任何代码。
结论先行：**成熟工业实践（无论中外）都收敛于"原文逐字不动 + 前置标注层"，而不是把小说改写成新剧本**。真正"重写剧本"的是另一个品类（广播剧/有声剧）。AI 有声书延续了同一结构：不重写文字，但在合成前加一道"画本/标注"工序。

---

## 一、欧美专业流程（ACX/Audible 体系）

欧美有声书默认是"朗读型"（narration），主播对着出版方提供的终校原稿**逐字念**（"read only the words on the page"，改文字需版权方批准，除明显 typo）。工作量的大头不在"念"，而在录音前的 prep（准备/标注）：

**Prep 阶段（进棚前）**
1. **先通读全书一遍**（first read）：在 iPad/平板上用 PDF 标注工具（Acrobat、PDF Expert）读。
2. **发音表（pronunciation guide）**：真实生词查字典、在页边写音标或贴音频链接；虚构人名/地名整理成清单，录完 prep 后发给版权方确认——"最坏结果是全书念错主角名字"。
3. **角色设定表（character sheet）**：推荐用 Excel 两个 sheet——发音表 + 角色描述（外貌/年龄/说话习惯），用于给每个角色"定声"（casting the voices）。
4. **在原稿上旁批**：音标、角色出场、重音提示等，本质是"给原文做旁批"，不改写文字。

**Checkpoint**：上传前 15 分钟样音（任选段落）给版权方确认音色与角色塑造方向，通过后才全量录制。

**Recording**：punch-and-roll 录音法（录错回滚即录即补）；经验值约 **6.2 实时小时 / 1 成品小时**（不含 prep）。Tantor、Podium 等出版方要求逐字朗读、一字不落。

**后期链**：剪辑（降噪/音量一致，"enhance the performance, not change it"）→ **审听（proofer）**边听边打时间码记录错漏 → **pickups 补录**（主播重录被标记句、剪辑师无缝拼回）→ 母带 → 按平台规格导出交付。

**行业标准**：
- ACX 提交必须声明 **unabridged（全本）/abridged（删节）**，业界绝对主流是全本；标删节必须真删，否则算误导。
- 技术规格：192kbps CBR MP3、44.1kHz、RMS -23~-18dB、峰值 ≤-3dB、本底噪声 ≤-60dB。
- ACX 默认**禁止未经授权的 TTS/AI 朗读**（有有限的 voice replica beta 和面向出版方的 AI 通道）。

## 二、中文行业流程：拆书/画本 + 定音 + 录音 + 审听 + 后期

中文有声书制作的标准岗位链：**统筹 → 画本（拆书）→ 配音（主播/CV）→ 审听（审校）→ 后期（对轨/混音/音效）**。

- **画本/拆书**是中文行业独有的"剧本化"环节，但它**不是改写**：把章节原文切成可配音的句子片段，逐段标注"旁白还是对白、谁在说、什么情绪"，用不同颜色标记不同角色，标注生僻字/多音字读音。文字本身保持原文。
- **定音/选角**：发试音需求、收集样章，编辑与作者共同投票定角；头部书选角"不亚于影视剧选演员"。
- **审听**：人工听成品挑错漏读音、情绪不符，回炉。
- **对轨**：后期把多轨音频与文本逐句对齐。

**品类光谱（改编程度递增）**：
| 品类 | 改编程度 |
|---|---|
| 单播/多播有声书 | 忠于原文，基本不改编 |
| 有声剧 | 适度改编：对话推进剧情 + 音乐音效 |
| 广播剧 | 重新编剧：全角色配音、可无旁白 |

**画本为什么难**（《万象有声创业笔记（二）》，2026）：
- 体例不可穷举：弯引号/角引号/冒号台词/无引号直引/剧本体/聊天体混用；
- 假对话高发：引用、书名、拟声、系统提示与真对话字形相似；
- 内心独白边界（"他心想："算不算台词）取决于产品定义；
- 依赖世界知识：别名、师徒亲属称谓、上下级、公会关系；
- 体例漂移：前十章规整、后面切剧本体，只采样前几章会系统性漏抽；
- 错误容忍度不对称：**漏真对话容忍度极低**，假对话可靠听感纠正。
- 该文方案：双引擎（全文 LLM V1 / 规则召回+LLM 归因 V2）+ 批次画像路由 + 人工抽检与 golden set 回归；"画本是整条链路的地基，错了越往后返工越贵"，但 AI 只能提置信度、**不能承诺自动证明"无漏对话"**。

## 三、AI 有声书管线（最贴近我们场景）

- **火山/豆包语音多角色演播**（2025-10 发布）：导入书文本 → 自动角色抽取、对话/旁白区分、判定说话人与情感 → 用户选音色合成；官方称音色匹配与对话归属准确率 >98%。
- **腾讯云万象有声**：上传 → 智能拆章 → 角色识别与画本（含人物小传、情绪标签、生僻字/多音字注音）→ AI 多角色配音 → 后期合成；宣传万字约 8 元、50 万字数小时出片。
- **ElevenLabs Studio**：上传稿件 → 分章 → 分配角色音色 → 统一发音表 → 调节奏 → 生成。
- **TTS 文本前端**（所有家共同的隐形工序）：文本规范化 TN（数字/单位/日期转读法）、多音字消歧（模型+词典）、韵律预测。这层做不好，后端声学模型再好也救不回来。
- 长文本 API 有字数限制，行业通用做法是**分段合成再拼接**（与我们的段级缓存思路一致）。

## 四、结论：最科学的流程

回答"直接念 vs 先改剧本"：**都不是照原文裸念，也不是改写成剧本，而是"逐字原文 + 标注层"**。三个理由：

1. **听众预期**：有声书的商业承诺是"全本、忠于原文"（unabridged 是 ACX 主流；中文平台同样标"完整版"）。改写引入"编辑错误"这个新错误维度，标注意味着零改写风险。
2. **改写想要的，标注层全都有**：角色区分、情绪、节奏、读音——这些好处全部来自标注元数据，不需要动正文一个字。
3. **工业分工**：欧美主播的 prep（发音表+角色表+旁批）、中文的画本岗、AI 管线的智能画本，是同一个东西的三种形态：**把非结构化小说转成"原文片段 + 演播元数据"的结构化序列**，然后按序列演播/合成。

**通用流程模板**（三地实践的最大公约数）：
原文清洗 → 通读全书 + 建发音表/角色表 → 标注（切分、归属、情绪、注音；不改写）→ 样章对齐（15 分钟 checkpoint）→ 批量产干音 → 审听打点 → 补录/重合成 → 母带与响度归一 → 交付质检。

## 五、对本仓库管线的启示（研究结论，未实施）

- `packages/audiobook` 现有工序：annotate.ts（文本归一化/井号修复）→ tts/ → srt → render-assets → video → assemble → youtube，**annotate 已经是行业意义上的"标注层"雏形**，方向与工业实践一致。
- 单音色解说路线：行业对应的是"播讲型有声书"，prep 重点 = 多音字/数字规范化 + 分段 + 停顿节奏，我们已覆盖大半；可对照 ACX 审听（proofer）思路做"听审 QA 打点"。
- 若上多角色（多人剧感）：需要真正的"画本"环节——旁白/对白分离、说话人归属、情绪标签，火山多角色方案（归属准确率 >98%）和上述 LLM 画本双引擎路线都是现成参考；注意"漏对话容忍度极低、AI 不能承诺无漏检"，需人工抽检门禁（与我们的质量门 SOP 同构）。
- ACX 的"15 分钟样章 checkpoint"与我们的"先样品再批量"质量门完全同构，业界背书了这套做法。
