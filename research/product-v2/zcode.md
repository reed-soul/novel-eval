## 一、自我诊断：八个产品病（对着代码说）

| # | 病 | 代码位置 | 病因 |
|---|---|---|---|
| 1 | **工具中心导航**：项目/评估/审计/有声书平铺，用户心智是"我的书"不是"工具箱" | Layout.tsx | 按代码包结构组织导航，不是按用户任务 |
| 2 | **实现细节泄漏**：v3/v4=渲染缓存目录名直接进 UI；whisper 模型/CER 阈值/TTS 引擎名全暴露 | Audiobook.tsx | 后端有什么就摆什么 |

## 二、定位（回答"是不是影视创作台"）

**是"小说 IP 一源多形态的创作台"，不是通用影视制片工具。**

理由：差异化护城河是"**源头可控的自动化**"——书是本系统自己写的（writer 管线），角色库/画本/发音表/场景图全部结构化在库（writer.db + project config），衍生成本极低。对标生态里"小说→推文→漫剧→短剧"已经是验证过的产业路径（AI 覆盖 ~90% 工序、成本 ~10%），但市面工具（一帧秒创/闪创/Toonflow）都从"贴入小说文本"开始——我们从"生成小说"开始，快一个身位。

StudioBinder 的制片流程隐喻可以借来组织信息架构（pre-production=写作/质检，production=制作，distribution=发布），但不要做成团队协作制片工具——用户是单人作者，协作/排期/通告单全是负资产。

## 三、信息架构（核心重构）

### 现状 vs 目标

```
现状（工具中心）                目标（作品中心）
─────────────────              ─────────────────
导航: 项目列表                   书架 Bookshelf（首页=我的作品）
     ├ 项目详情                      └ 《最后一班森铁》书内 Hub
     ├ 质量评估                          ├ 概览（进度/最近/快捷动作）
     ├ 逻辑审计                          ├ 创作（大纲→章节→修订，现有）
     ├ 有声书 ←全局混入                  ├ 质检（eval+audit 合并，都是"检查"）
     └ 模型配置                          ├ 衍生 Derivatives ★2.0 核心
                                            ├ 有声书（集列表+制作流水线）
                                            ├ 精简短篇（规划）
                                            ├ 剧本（规划）
                                            ├ 漫剧/AI短剧（规划）
                                            └ + 更多形态…
                                          └ 设置（书级配置：引擎/发音表/班底/场景图源）
全局: 模型配置 → 收进全局设置（低频）
```

### 关键决策

1. **书（Book）是唯一一级对象**。导航从 5 项砍到 2-3 项：书架 / 全局设置。评估、审计、有声书全部降级进书内。
2. **衍生（Derivative）是书下的二级对象**，每种形态一个 tab/卡片。有声书只是第一个落地的衍生形态——这直接回答了"十个小说一百个 item 怎么找"：书架分组→书→衍生→集，四层 drilling，每层不超过一屏。
3. **run 目录（v3/v4）降级为纯内部缓存**：`dist/audiobook-cache/<bookId>/`，UI 永不出现版本号；产物按"每本书每集取最新可用"解析。旧 v3 直接归档不进 UI（回应用户"v3 废弃不该出现"）。
4. **书级配置中心承载 90% 参数**（对标 CapCut 的"项目模板"模式）：引擎、并章数、场景图源、发音表、音色班底、冷开场开关——首次制作向导时建立，之后每集制作只剩一个决策："哪些章节"。
5. **集有状态机**：`草稿 → 审听中 → 需人工复核 → 就绪 → 已发布`。卡片按状态着色/排序，状态即行动指引（对齐用户"看不懂 P0 29 是什么"的抱怨——技术指标收进详情页）。

## 四、核心旅程：制作下一集（替换现在的表单）

现状：点"构建新集"→ 7 参数表单 → 猜。
目标（向导式，对标喜马拉雅 A+ 的四步工作台 + Descript 的 script-first）：

```
集列表页                    Step1 选章节                Step2 预览确认              Step3 制作
┌─────────────┐      ┌──────────────────┐      ┌──────────────────┐      ┌────────────────┐
│ EP01 ✅已发布 │      │ 章节流（可视化）    │      │ 将产出：           │      │ 进度+直播控制台   │
│ EP02 ✅已发布 │  →   │ ▣1 墙里的骨头     │  →   │ EP03｜3-5章        │  →   │ ▶ TTS 12/46    │
│ EP03 🟡审听中 │      │ ▣2 顺达公司       │      │ 预计 18 分钟       │      │ ▶ 渲染 …       │
│ ＋制作下一集 ★│      │ ▣3 最后一班小火车  │      │ 用书配置：豆包班底   │      │ 完成→自动审听    │
└─────────────┘      │ （已用章节置灰）    │      │ [调整高级参数▸]     │      └────────────────┘
                     └──────────────────┘      └──────────────────┘
```

- 「制作下一集」常驻集列表尾部（现有"等待构建"虚线卡的强化），**自动预选下一批未制作章节**——多数情况一路"下一步"。
- 高级参数（引擎/试产字数/起始集号）折叠进 Step2 的"调整高级参数"，默认继承书配置。
- 制作完成自动跑审听（现在要手动点"审听本版本"）——流水线自动衔接，参数（fix/srt/模型）收进集详情的"重新审听"高级菜单。

## 五、组件品质方案

- **引入 Radix UI primitives**（无样式、可访问性开箱）+ 继续用现有 design tokens 自定义外观——不上完整 shadcn（本地单人工具，控制依赖面）。
- 优先替换：Select（章节/引擎选择）、Dialog（向导容器）、Tabs、Checkbox/Switch、Toast（任务完成通知）。
- 表单=向导步骤化后，原生组件露脸机会本身就少了 80%。

## 六、2.0 路线图（分期可拍板）

| 期 | 主题 | 用户价值 | 工程内容（复用为主） | 量级 |
|---|---|---|---|---|
| **M0 可用性抢救** | 导航与有声书重构 | "找得到、敢点、看得懂" | 书架首页+书内 Hub 路由；有声书迁入书内；run 隐藏（backend runs API 按 bookId 聚合取最新）；构建向导三步；集状态机；v3 归档 | 1-2 天 |
| **M1 制作流水线** | 一键出集 | 从"配置参数"到"选章节点确认" | 书级配置中心 UI；制作完成自动审听；审听复核工作台（坏段列表→试听→一键重合成）；发布登记（链接/平台状态） | 3-5 天 |
| **M2 质检合一** | 质检成为书内一环 | eval/audit 不再是孤立工具 | 书内质检 tab（跑全本审计+评估报告聚合）；投稿质量门（platforms.yml 红线）挂到"就绪"状态前置 | 2-3 天 |
| **M3 衍生扩展** | 一源多形态落地 | 同一本书长出第二种作品 | 衍生框架抽象（Derivative 接口：类型/配置/管线/产物）；精简短篇（LLM 压缩→短篇集）；剧本（画本→剧本格式化）——两者复用画本/角色库/发音表 | 1-2 周 |
| **M4 漫剧/短剧 PoC** | 视频形态验证 | 场景图+分镜→AI 漫剧 | 分镜抽取已有（v3 scenes.json）+ 生图管线（Seedream）+ TTS → 静态分镜漫剧 MVP；接 i2v（火山/fal）看效果再定 | 1-2 周 PoC |

依赖关系：M0→M1 严格先后；M2 可与 M1 并行；M3 依赖 M1 的配置中心；M4 独立可 PoC。
