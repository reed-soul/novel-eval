## 1. 工具测评：YouTube.js（youtubei.js）好不好用

| 通路 | 状态 | 说明 |
|---|---|---|
| 搜索 | ✅ 开箱即用 | 关键词/排序（按播放量）/翻页都稳，本报告 132 条数据全靠它 |
| 频道数据 | ⚠️ 半残 | `getAbout()`（订阅数/国家/总播放/视频数）可用；`getVideos()` 在新版频道页上解析失败（返回 0 条）——用**频道 RSS**（官方提供、近 15 条含播放量）替代，反而更稳 |
| 视频详情/字幕 | ❌ 被风控锁死 | 未登录一律 `LOGIN_REQUIRED`（"Sign in to confirm you're not a bot"），`getInfo`、captions、transcript 全空；裸调 `get_transcript` 端点和 cookie 重放也绕不过（PO token 风控） |
| 替代方案 | ✅ **yt-dlp + Chrome cookie** | `yt-dlp --cookies-from-browser chrome` 完全可用（自动解 JS 挑战）；抓字幕/简介/元数据全靠它 |

**结论：读方向的活能干，但 YouTube.js 只能干一半（搜索+频道概况），字幕层必须 yt-dlp 带 cookie。** 脚手架在 `research/yt-competitors/`（复跑方法见文末）。

**附带发现：赛道字幕覆盖率极低**——14 条头部样本里只有 4 条有字幕（覆盖率 ~30%），夜语轶事、灵异讲述屋、十三兰德的视频全都没配字幕。上传正式中文字幕 = 搜索流量和无障碍推荐的实际差异点，**你的 EP01 已经做了**（zh 字幕轨在档），保持。

### 三个结构性观察

1. **订阅数 ≠ 播放量**。鲶鱼夜话 2 万订阅做到 1.6 万中位播放（播放/订阅比 0.84），憨小胖 7.9 万订阅只有 5.8K（0.07）。决定播放的是**选题钩子 + 标题**，不是粉丝盘——新频道冷启动在这个赛道不是死局。
2. **爆款集中度极高**：中位播放 4-6K 的频道，靠单条 10 万+ 爆款拉起全部流量（夜语轶事中位 4K、峰值 25.8 万）。这个赛道的游戏是**持续出钩子，等爆款**，不是细水长流。
3. **两条赛道在死，一条在活**：书评解读（十三兰德停更）和无钩子纯推文（百播俱乐部）在退化；「一口气看完·完结文·冷开场直接讲」的叙事型内容在稳定出爆款。

## 3. 赢家打法拆解

### 标题公式（14 条头部样本归纳）

- **公式 A · 夜语轶事**（爆款机器）：`【民俗|懸疑】一口氣看完，+ 猎奇钩子句 + 全文完結`——钩子句是"我们村的男人都喜欢肥胖的女人，原因竟然是。。！"这种**具体到不可能不好奇**的悬念句。
- **公式 B · 灵异讲述屋**：`【完结】《规则名》+ 冷开场第一句直接当标题`（《凌晨宿舍规则》熄灯前十分钟，班级群突然出现匿名消息…）——**标题即开场白**，搜索和点击两头吃。
- **公式 C · 鲶鱼夜话**：`【高能預警】+ 题材词 + 具体意象`（地上灑滿冥紙，白臉女鬼「抬棺」哭花臉）。
- **反例**：`高评分完结悬疑小说，一口气更完！#悬疑#文荒推荐`（小四推文）——零信息量，天花板 5.8K。

### 开场文案（4 条有字幕样本逐句分析）

- 憨小胖（动画）：**10 秒内进入设定**（"七月半鬼門開…"），语速 ~270 字/分钟，无废话直接讲事。
- 鲶鱼夜话（播客）：有 30 秒+ 的节目仪式（点赞护体/自我介绍）——播客品牌这么玩成立，但那是在吃**真实感**人设红利，不适合 TTS 叙事形态。
- 你的冷开场管线（16 秒钩子→正片）与赢家形态一致，**方向不用改**。

### 简介与标签

- 夜语轶事：简介里**堆满 hashtags**（#推文 #完結文 #一口气看完系列 #懸疑 #民間故事…）+ sub_confirmation 订阅直链。
- 灵异讲述屋：品牌句 +「每日更新」承诺 + 订阅 CTA。
- 十三兰德：人话编辑式简介，只写书名和一句话钩子。
- **全部 14 条无一使用原生章节（chapters）**，连 53 分钟双故事合集都没有。

## 5. 优化清单

### P0 · 发 EP02–05 前就改（成本≈0）
1. **标题改钩子优先**：`【完结有声】墙里的骨头：拆墙拆出一九九八年的旧账｜最后一班森铁 01`——套公式 B（片名+冷开场句），集数挪到末尾或只留播放列表里。
2. **原生章节修复**：把简介里的时间轴**每个时间戳独占一行**、第一行必须 `00:00` 开头（`⏱ 本章时间轴` 这种前缀行放没所谓），YouTube 才会解析成进度条章节。你的 SRT 时间戳本来就有，零成本，且**全赛道无人使用**。
3. **简介加 hashtag 阵**：`#悬疑小说 #有声书 #完结文 #一口气看完系列 #悬疑 #犯罪 #东北`——对着夜语轶事的标签阵抄结构。
4. **更新节奏**：5 集别一次全发也别压着，**2–3 天一集**，维持频道活跃信号。

### P1 · 一个月内验证
5. **长度实验**：EP 压到 35–40 分钟（或把现有一集拆两半），对照组留着 56 分钟版，跑 2–3 集看完播率差异。
6. **爆款钩子选题库**：每集标题先写 3 个钩子句候选，按公式 A 的「具体到不可能不好奇」标准筛——森铁的「清林款对不上」「车过不去桥」都是现成钩子。
7. **《物业管家不想破案》用公式 B 起量**：规则/单元剧气质更贴灵异讲述屋的「标题即开场」打法。

### P2 · 结构性
8. **「一口气看完」全本版**：等 5 集发完后，剪一个全本 4 小时版单独发布（夜语轶事证明全本完结是爆款形态，且长视频广告分成友好）。
9. **对标的内容雷达**：本目录脚本可随时复跑，建议每月跑一次看夜语轶事/灵异讲述屋的新爆款标题在变什么。
10. **暂不建议学**：鲶鱼夜话的播客仪式（吃真实人设红利，与 TTS 形态冲突）、憨小胖的动画（制作成本另一个量级）。

## 6. 复跑方法

```bash
cd research/yt-competitors
npm install
node scan.mjs      # 关键词扫描 → data/scan.json（YouTube.js 搜索，无需登录）
node pick.mjs      # 选各频道头部视频 → data/pick.json
node channels.mjs  # 频道深挖 → data/channels.json（getAbout + RSS）
node me.mjs        # 自己频道 → data/me.json
# 字幕（需 Chrome 已登录 YouTube；未登录会被 bot 墙拦截）
node deep.mjs      # 开场解析+简介 → data/deep.json
```

字幕批抓：`yt-dlp --skip-download --cookies-from-browser chrome --write-auto-subs --write-subs --sub-langs "zh.*,zh" --sub-format json3 -o "data/transcripts/%(id)s" <URL>`

注意：youtubei.js 的 `getVideos()` 在新版频道页解析失败（v13.4.0），频道视频列表一律走 RSS；`getInfo`/字幕相关 API 被未登录风控锁死，别再试。
