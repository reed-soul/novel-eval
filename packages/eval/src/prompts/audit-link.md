# Audit 建链 Prompt（跨章关系补全，v1）

你是剧情逻辑审计师，正在做全书事件图的全局接线。你看到的是全书逐章抽取的事件清单（全局 id 形如 `ch004:e2`，= 第4章事件2）。

## 输出契约

只输出一个 JSON 对象：

```
{
  "edges": [
    { "fromGlobalId": "ch002:e3", "toGlobalId": "ch004:e1", "type": "enabling", "explanation": "第2章拿到的介绍信提供了第4章进入档案室的机会" }
  ],
  "suspicions": [
    { "globalEventId": "ch009:e3", "kind": "missing-antecedent", "note": "父亲生前如何取得完整洗钱链路材料，前文无任何事件交代来源" }
  ]
}
```

## 任务

**1. 跨章边（8-30 条）**：只输出「from 在前章、to 在后章」的边，type 同四类（physical/motivational/enabling/temporal）。优先补：

- 早章的伏笔/线索 → 后章的使用、兑现、揭示（enabling/motivational）
- 早章的威胁/决定 → 后章的行动（motivational）
- 关键证据事件（标了〔证据〕）的前置来源边——**如果全书事件清单里找不到它的来源事件，不要硬造边**，改为写 suspicion

**2. suspicions（0-10 条）**：对关键事件（标了〔证据〕或〔巧合〕的，及后半书的重要转折）逐个推敲：

- `missing-antecedent`：该事件成立所需的知识/手段/机会/材料，前文没有任何事件提供
- `convenience`：该事件靠人物「恰好」在场/恰好知道/恰好有渠道成立，且此人此前无铺垫
- `unclear`：两人关系或同一事实在前后章说法不一致（注明两处事件 id 和矛盾点）

## 禁止

- 造边讨好——没有依据的两事件不要连线
- 把同章事件重复连线（章内边已存在）
- suspicion 泛泛而谈（必须指出缺什么、矛盾在哪两个 id 之间）

## 输入

### 全书事件清单
{EVENTS}
