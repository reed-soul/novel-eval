# 最终优化方案（2026-10-22 定稿）

> 本文取代 `docs/architecture-review-2026-10-21.md` 的「优化方向与优先级」一节。
> 架构评审的三层裁决、16 项薄弱环节、证据仍然有效；**优先级全部重排**，因为目标函数变了。

---

## 0 一句话裁决

**旧 P0 六条：删 2、降 2、留 2（其中 1 条换掉检查项），新增 3 条。**

判断依据不是"架构债有多严重"，而是：**规格从「4 万字 / 18 章」换成「1.2–1.5 万字 / 单篇」之后，哪些债自动消失、哪些债被放大。**

---

## 1 旧 P0 逐条裁决

| 旧编号 | 内容 | 裁决 | 理由 |
|---|---|---|---|
| P0-1 | 门禁可执行化（exit code + 后置断言） | **保留，换检查项** | 仍然是最重要的单点。但门里**不该放"总分 ≥85"**——实测均值 86、σ 2.3，这个门不筛选任何东西。应放：规格 12 项 + 因果三类。已落地 `scripts/spec-gate.py` |
| P0-2 | 章级门接异源 evaluatorEngine | **降级 P1** | 章级门存在的理由是"单章看不见全书"。1.2–1.5 万单篇共 8–9 节，一节≈全篇 1/8，"看不见全书"的问题基本消失。异源评审仍要做，但改由 audit 双红队承担（已有），不必给章门接线 |
| P0-3 | 补丁走 publishChapterEditWithExtract + 自动 rebuild | **降级 P2** | 16 个 `patch_*.py` 的成因是"18 章里改一章、后面 10 章 state 全废"。单篇 8 节、1.5 万字，正确做法是**整篇重写**而非外科补丁。补丁场景大幅萎缩。但"book.md 与 DB 双写"这个事故源要单独解：**DB 单向导出，book.md 只读**，比接产品路径简单一个数量级 |
| P0-4 | 先打通 1 部视频闭环 | **删除** | 用户明确：暂不做视频。此事从"最贵架构损失"降为"不是当前问题" |
| P0-5 | 确定性连续性门（死人出场/facts 矛盾/伏笔超期） | **删除（暂缓）** | 为「60 章 / 30 万字长篇」设计。1.2–1.5 万单篇不存在跨 60 章的一致性问题。转长篇时再捡回 |
| P0-6 | 伏笔埋点表前验化（`plants[]` 进蓝图） | **删除，思想保留** | 同上，数据结构改造无收益。但"伏笔必须前验"的思想保留——降维成 A 卡里的**「反转三问」表**，写进 prompt 即可，不需要动 schema |

**净结果**：旧 P0 合计 20–31 人日的工程量，砍到 **10–14 人日**，其中真正必须本周做的只有 **2–3 人日**。

## 2 为什么规格一改，这些债就消失

```
4 万字 / 18 章 / 2600 字一节
  ├─ 跨章一致性难  → 需要 P0-5 连续性门、P0-6 伏笔表（各 5–10 人日）
  ├─ 单章改一章废十章 → 需要 P0-3 补丁产品化（3–4 人日）
  └─ 章门只看单章  → 需要 P0-2 异源章门（1–2 人日）

1.2–1.5 万字 / 8–9 节 / 1600 字一节
  ├─ 全书能一次读完 → 上面三项全部失去意义
  ├─ 改一次 = 整篇重写 → P0-3 场景消失
  └─ 新增的真问题 → 规格合规、因果工程、结局兑现（这正是投稿被拒的三条）
```

**这是本次方案最重要的一条判断**：过去半年的工程投入有相当一部分，是在为"18 章 4 万字"这个选择付利息。而盐选的最优区间是 1–2.5 万字——**把规格改对，比把管线修好更省力**。

## 4 新方案

### P0（本周，2–3 人日，其中 1 项已落地）

| # | 动作 | 改动面 | 工作量 | 为什么排这个序 |
|---|---|---|---|---|
| **P0-A** | **规格门 `spec-gate.py`**（已落地）+ 接入夜跑：拼书后立即跑，FAIL 不进 eval | `scripts/spec-gate.py`（已写）、`daily-novel-prompt.txt` 第四步 | 0.5 人日（接入） | 42/42 不合格说明这是唯一的真门。且纯字符串、零 token、秒级 |
| **P0-B** | **规格换血**：18 章 / 4 万字 → **9 节 / 1.35 万字**（1600 字/节）、强制第一人称、结尾四件套、反转三问 | `scripts/daily-novel-prompt.txt` 第一/三/四步 | 0.5 人日 | 这是"过稿"与"单集短剧"两条目标的唯一交集。不做这条，其余全是空转 |
| **P0-C** | **因果门硬阻断**：audit 的 `missing-enablement` / `coincidence-driven` / `causal-break` 三类**不可人工判噪声** | prompt 第四步第 3 项 + `audit/aggregate.ts` | 1–2 人日 | 这三类占 P0 的 **79.2%**（803 条中 636 条），且"判噪声"是当前唯一的绕过口 |

**关于 P0-C 的机理**（必须写清，否则改不动）：现有 prompt 原文是——

> "两跑 P0 名单合并去重后逐条回原文核对，真 P0 外科补丁修…**已核仍报噪声判真实 P0=0 过门**"

这句话把裁决权交给了疲劳的人在凌晨四点做判断。历史结果是：`TOPIC-LEDGER.md:157` 记录"真 P0=0"的稿子，同一文本三次跑分 P0 波动 2.3 倍（3/4/7）。**改成**：三类因果缺陷一律不豁免，判噪声必须提交"原文反证段落 + 检索位置"，且反证要能通过第二次独立检索（异源模型）。

## 5 两条策略建议（比代码重要）

### 5.1 砍掉番茄，只投盐选

三条理由，都是硬约束：

1. 番茄「短故事」编辑器**官方不支持分章节发布**，我们的体例直接命中 2026 低质治理的「格式混乱」；
2. 番茄要求灵异**必须给现实解释**（人为/心理/梦境），而油管民俗怪谈赛道要的正是"鬼是真的"那层张力——两端需求互斥；
3. 2026 年 5 月番茄拒签低质 11.27 万本、7 月拒签 AI/水文 16 万本。**"日产一部"本身就是被打的量产特征**。

盐选则相反：1–2.5 万字最优区 = 单集视频底本，第一人称 = 视频解说人称，民俗怪谈有位置（民俗外壳 + 人性内核）。

**一颗试金石够了。** 番茄留作"盐选未过时的二投"（未发布不算破首发）。

### 5.2 保留日产节奏，但把产能搬进改写

用户不想停日产——这是对的，但省下的成本要换个花法：

```
旧：4 万字 × 1 遍  = 产出 1 部，规格 0 通过
新：1.35 万字 × 3 轮 = 产出 1 部，第 1 轮生成 + 2 轮定向重写（因果/结局/开篇）
```

同样的 token 预算，**从"写得多"换成"改得深"**。依据：因果缺陷 79.2% 是重写能修的，不是调 prompt 能修的；而 4 万字稿一次改不动。

## 7 验收标准（怎么知道这方案有用）

不用看评分。看四个数：

| 指标 | 现在 | 30 天后目标 |
|---|---|---|
| `spec-gate --profile salt` 通过率 | 0/42 | ≥ 8/10 |
| audit 三类因果 P0 数 | 均值 4.6/部（三类占 79.2%） | ≤ 1/部 |
| 结局四件套齐备 | 3/8 | ≥ 8/10 |
| 盐选投稿实际结果 | 0 次过稿 | 至少 1 次过稿或进入编辑沟通 |

**最后一句提醒**：过稿是结构合格证，不是质量真值。真正的质量真值是"观众愿不愿看完 15 分钟"——那个数据现在一个都还没有，因为视频还没做。所以本方案只对"结构合格"负责，不对"好看"负责；"好看"要等第一条视频上线后才有真值。
