# v3 处方草案评审报告

评审基准：`docs/research/2026-10-25-v3-prescription-draft.md` × 真实代码链路（`blueprint-chapters.md` / `writing-grammar.ts` / `quality-gate.ts` / `config/writer.yml` / `chapter-generation-service.ts`）。先给一个总判断：**三张处方落点全部选对了层，但处方 3 的阈值论证不成立，处方 1 有一个会把题材名写死进通用模板的措辞 bug，处方 2 有一处会自己触发防重复闸门的例句。**

## 0. 关键链路事实（评审依据）

先把处方落点对应的真实代码行为钉死，后面所有判断基于此：

1. **蓝图 summary 确实进每章正文 prompt**。活链路在 `services/chapter-generation-service.ts:143`（`蓝图摘要：${outline.content.summary}`）——注意 `chapter-next.md` 是死模板（文件头已标注归档），改蓝图规则**只能改 `blueprint-chapters.md`**，别改错文件。
2. **蓝图层规则先例已验证有效**。`blueprint-chapters.md:25-26` 的灵异规则契约/主角智斗就是同一层的模板级规则，battle3 判定“强效/中效”。这是“设计类约束放蓝图层可靠”的直接实证。
3. **闸门层已有可镜像的硬下限模式**。`quality-gate.ts:220-228` 的 `minCharacterization` 硬下限（结构伤总分再高也不过闸）就是处方 3 要的形状，`emotionalResonance` 维度在 eval 八维里已存在（`packages/eval/src/types.ts:69`），`assessChapters` 每章都打这个分。新增 `minEmotionalResonance` 是 ~10 行镜像 + `config.ts:42,124` + `writer.yml` 三处管道，成本低且有先例。
4. **revise 反馈闭环已通**。低于硬下限 → 维度进 `lowDims` → `buildFeedback` 带该维度 analysis 注入重写 prompt（`quality-gate.ts:323`）。地板不是死数字，是有反馈回路的。
5. **闸门对 v2 根本没开过**。battle3 明说 v2 是无门槛 auto 生成。所以处方 3 有一半其实是“把闸门打开”这个动作本身，而不只是新阈值。

## 1. 逐张处方：会不会生效，落点对不对

### 处方 1（每章情感拍点进 summary）——落点正确，会部分生效，措辞有一处 bug

**蓝图层 vs 闸门层在这里不是二选一，是管两件事**：

- 蓝图层管**结构在场**——这场戏有没有被设计出来。v2 的病是“6 章没有一场与椿伯的情感互动”，这是**章级看不见、书级才成立的缺失**：每章单看都可能有点情绪（对秦朗、对物证），只是对象全错了。per-chapter 的 emotionalResonance 地板**抓不住这种病**——每章 76 分 × 6 章，聚合起来照样是“没人为角色流泪”。所以结构缺失只能靠蓝图层约束，这正是处方 1 落点对的原因，且和灵异契约同型（灵异契约也是“设计层”约束，实证有效）。
- 闸门层管**执行温度**——设计出来了正文写没写热。这是处方 3 的职责。

**两个具体问题**：

1. **summary 预算只有 50-150 字**（`blueprint-chapters.md:31` JSON 示例）。主线索 + 情感拍点挤进 150 字，拍点分到约 20 字（“回家给椿伯递了碗药”级别）。这不足以触发敷衍填空调用，但足以让拍点被正文薄写。缓解恰好是处方 3：拍点写了但正文冷 → emotionalResonance 低 → revise 反馈点名。**处方 1+3 是一对，单独任何一张都失效**——草案没把这层依赖写明，建议在处方里显式标注。
2. **措辞 bug**：草案原文“优先椿伯/奶奶的记忆载体”——这是本 topic 的专名，不能进通用模板。模板里有 `{CHARACTERS}` 注入，应改写为“角色列表中与主角情感联结最重的人物（或其记忆承载者）”。这个 bug 不改，下个题材直接失效。

### 处方 2（取证从物转向人）——一半对，一半该搬家

`writing-grammar.ts:23` 的【主角用脑子】确实注入每章 prompt（`chapter-generation-service.ts:136→149`），改写成本≈0。但草案的替换文案有两个问题：

1. **固定例句风险**：文案里的示例句“指纹咬合的瞬间，我想起按手印那只手如今在给谁喂饭”进入**每章**的负面清单。LLM 对负面清单里的正例有强烈的照抄倾向——一旦第 3 章抄了、第 5 章又抄，跨章 shingle 重复检测（`repetition.ts`）会把它标成 hotspot，形成“指令自己喂重复热点给闸门”的自伤回路。例句要么删掉，要么标注“形式如此，严禁照抄原句”。
2. **结构性要求放错了层**：“每章至少一次由对话/对视/触碰产出关键线索”是设计层约束（线索从哪来是蓝图决定的，不是行文决定的），塞进十条长的负面清单中段，遵从率我估 50-70%。应该上移到 `blueprint-chapters.md` 与处方 1 合并（“情感拍点即线索场景：本章至少一条关键线索须从这场人际互动中产出”）——蓝图层先例的遵从率远高于指令清单中段。`writing-grammar.ts` 只留行文指引（镜头对准物主的脸/手/呼吸）。

### 处方 3（情感维度闸门 + 双本取优）——机制对，阈值论证不成立

代码落点完全成立（见事实 3/4）。但阈值 72 的推导有个测量工具错配：**74 是双盲评的书级分数，闸门地板卡的是 per-chapter assess 分，两者是不同 prompt、不同 rubric 的两把尺子**。eval 自己的 reduce rubric（`reduce-r2.md:48`）写的是“情感共鸣 60-75 = 起伏一般”——按这把尺子，v2 那种“解谜机器”章节可能被打在 65-75 区间，72 的地板可能一次都不触发，也可能次次触发，**纯粹是掷骰子**。正确做法见下节处方 3'。

双本取优：见待评审问题 5。

## 2. 五个待评审问题逐一回答

**Q1：情感拍点进 summary 会不会被敷衍填空？要不要改到闸门层检测？**

会一定程度的敷衍（150 字预算决定了他只能“填”），但这不是致命的——因为正文不执行时会被处方 3 的地板接住（拍点在 summary 里 → 正文不写热 → 情感共鸣低 → revise 反馈点名）。**不要改成“闸门检测 summary 是否含拍点”**——那检测的是蓝图文本而不是正文质量，是检测了形式放弃了实质。正确的冗余是：蓝图保证场景被设计、闸门保证场景有温度。另外“每章强制”可能产生场景级套路（连递 6 次碗），但 prose 层的照抄有防重复闸门兜底，场景层的重复靠“与本章线索勾连”约束自然稀释，不需要再加形式多样性规则——加了就是过度设计。

**Q2：“物挂人”指令的遵从率？要不要 eval 加“物-人勾连”维度？**

指令层遵从率中估 50-70%（负面清单中段 + 无反馈回路），所以我把结构性部分上移蓝图层（见处方 2 评审）。**不要新增 eval 维度**：一章“线索全来自物、活人无温度”的稿子，emotionalResonance 自然就低——现有维度已经覆盖了这个信号的检测面；且 eval 的 r4 已支持“小说特有检查项”（worldbuilding/pov/padding/hook）作为逃生门，真要加也是挂那里，不值得动八维 schema。加维度是本草案最明显的过度设计倾向。

**Q3：minEmotionalResonance=72 是否形同虚设？**

“v2 盲评 74 > 72 所以 v2 过闸”这个论证**无效**（两把尺子，见上）。但“这个门是不是形同虚设”是真问题，答案是：**先校准再定数**。v2 的六章正文和 skill 版六章都还在盘上（projectId e3e6ccfa + battle3 稿），跑一次现成的 eval 拿 per-chapter emotionalResonance 分布，零代码成本，然后取“v2 分布上沿 vs skill 版分布下沿”之间。我的预判是落在 75（与 minCharacterization 对齐——两者本就是同一类结构伤），但这要数据说话，不是拍脑袋。

**Q4：遗漏的处方？**

有，一条结构级的，直接回应我在 battle 系列批过的 v1“核心人物第 1 章即死”：**情感锚点人物存活约束**。v1 椿伯第 1 章死、v2 换成奶奶开局身死——管线连续两版都选择“用死人供情感”，因为灵异题材开局死亡是最省事的钩子。不堵这个口子，处方 1 的“记忆载体”条款会被继续钻空子（每章对着遗物抒情照样满足“物件传递”字面要求）。落点 `blueprint-act.md`（谁死、何时死是幕级设计决策）+ `blueprint-chapters.md`：核心情感人物不得在第 1 章死亡或永久离场；若题材设定其已亡故，必须有一个活着的关系承载者在第 2 章前登场并与主角有对手戏。

**Q5：双本取优会不会过拟合裁判偏好？**

n=2 谈不上系统性过拟合——这不是 best-of-50 的 selection pressure，只是方差控制（对齐 skill 版每章被闸门拦 6 次的迭代强度）。真正的偏差源是**选优标准用了自家 eval 的分**，而盲评是独立裁判——但这正是实验目的（验证管线自评与盲评的相关性），保留这个 gap 反而有信息量。两个注意：① 明确标注这是**验证期跑法，不是生产处方**，不写任何代码（草案也没有代码落点，正确）；② 两本各自记录 gate 拦截次数与维度分布，这是判断“处方生效还是采样运气”的唯一证据，别只留最终稿。

## 3. 过度设计与成本低估

| 项 | 判定 |
|---|---|
| 新增 eval“物-人勾连”维度（草案问题 2 的隐含选项） | **过度设计**。emotionalResonance 已覆盖检测面，r4 特有检查项是现成逃生门。砍掉。 |
| 处方 2 的长文案+固定例句 | **过度设计 + 自伤回路**。负面清单条目该是一行一条可判定的禁令，不是带文学示范的段落。删例句。 |
| 处方 1 硬编码椿伯/奶奶 | **bug**，下个题材即失效。泛化为“角色列表中情感联结最重者”。 |
| 双本取优 | 成本×2 可接受，但**仅限验证期**，草案未标注。 |
| 阈值 72 缺校准步骤 | **成本低估的镜像**：校准只要一次现成 eval 跑批（v2 六章已在盘上），比争论 72 还是 75 便宜得多，草案漏了这步。 |
| “每章强制拍点”的场景级重复风险 | 不需要额外机制（见 Q1），加了就是过度设计。仅此提醒。 |
