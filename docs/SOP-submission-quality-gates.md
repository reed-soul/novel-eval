# 投稿前质量门 SOP（可重复执行流程）

> 版本：v1（2026-08-28）
> 背景：《最后一班森铁》三次内部评测 88/A，投知乎盐选被拒（"文笔风格、剧情逻辑经不起推敲，读者代入感较弱"）。
> 事后诊断：评测用了改稿权重（marketPotential 仅占 4%，15 章里它全是最低维 68-78 却被总分淹没）、无平台标尺、写书评书同一模型。
> 本 SOP 把教训固化为两道机器门 + 一张人工清单，全程可在 Web 端自助操作，CLI 等价命令附后。

---

## 流程总览

```
书稿（writer.db 项目 / 全本 md/txt）
   │
   ├─① 质量评估（投稿模式 + 平台标尺）──→ 投稿门 verdict
   │      platform=番茄/盐选/豆瓣，profile=submission
   │      红线未过 = ⛔ 不建议投稿，先改稿
   │
   ├─② 剧情逻辑审计（推敲器）──→ P0/P1/P2 逻辑洞清单
   │      修 P0/实锤 P1 → 复审 → 硬矛盾零复发 = 通过
   │      （判据是"硬矛盾零复发"，不是 P0 计数归零）
   │
   ├─③ 投稿物料（章节切分/简介/封面/笔名）
   │
   └─④ 平台操作（人工：开户实名/上传/报名问卷）
```

**两道门的分工**：①管"这本书适不适合这个平台"（商业匹配）；②管"剧情经不经得起推敲"（因果严谨）。盐选那句话的两半，各归一门。

## ① 质量评估 + 投稿门

### Web 操作
1. 打开 `质量评估` 页（`/eval`）
2. 选择来源：上传全本 txt/md，或直接选已有项目（自动导出正文）
3. **评估模式选 `submission`（出版社投稿审查）**——市场分权重 20%，不再被文学分平均掉
4. **投稿平台必选对应平台**：
   - `知乎盐选`：第一人称亲历感、黄金三章、知乎体短段、女频付费盘、结局正义实质伸张
   - `番茄小说`：第三人称友好、首章主角早出场、章末钩子、完结爽感
   - `豆瓣阅读`：文学向、慢热友好、影视通道
5. 跑完进报告页，看顶部**投稿门横幅**：
   - ⛔ 红牌 = 平台红线维度未达标（如番茄 marketPotential<80 或 pacingRetention<80），列出每条原因——**不建议以当前状态投稿**
   - ✅ 绿牌 = 红线全过
   - 无论红绿，横幅都会标出**全书最低维**——森铁教训：最低维最容易被总分平均掉，优先处理它

### CLI 等价
```bash
novel-eval evaluate 全本.md --profile submission --platform fanqie \
  --genre 犯罪悬疑 --audience 成年男性
```

### 红线速查（`packages/eval/src/config/platforms.yml`）
| 平台 | 红线维度 |
|---|---|
| 知乎盐选 | marketPotential ≥ 80，emotionalResonance ≥ 80 |
| 番茄小说 | marketPotential ≥ 80，pacingRetention ≥ 80 |
| 豆瓣阅读 | 无红线（文学向不卡商业分，仍报最低维） |

改红线 = 改 yml，不需要动代码。

## ② 剧情逻辑审计（推敲器）

### Web 操作
1. 打开 `逻辑审计` 页（`/audit`）
2. 上传全本或选项目；填类型（注入公平/世情探针上下文）；高潮章号选填（缺省=最后一章）
3. 等待约 5-10 分钟（约 ¥2/本，15 章规模），报告页按 P0/P1/P2 筛选查看
4. 每条洞含：类型（11 类）、严重度、证据章节与原文摘录、手术级/重写级修法建议

### CLI 等价
```bash
novel-eval audit 全本.md --genre 犯罪悬疑 --climax-chapter 14
```
报告 JSON：`packages/eval/data/reports/<taskId>/audit.json`（Web 端在 `packages/web/data/audits/<taskId>.json`）

### 判定标准（重要，别用错）
- **推敲器是"找茬雷达"，不是及格线**：P0 计数有 ±4 的运行间波动
- 通过判据 = **硬矛盾（时间线/物理/证据去向类）修复后零复发**
- 已知盲区（视为噪声，人工复核）：
  - 闪回章会被报"时间线倒错"
  - "线索埋了但高潮才揭示"的公平性写法会被报"前置缺失"（其实是写法）
  - 1998/2010 式双线闪回的跨章因果常连不上
- 修稿后**必须复审**验证零复发，不要修完直接投

### 11 类洞速查
因果断裂 / 巧合驱动 / 孤悬情节 / 时间线矛盾 / 事实矛盾 / 动机缺失 / 使能缺失 / 线索不公 / 罪罚错配 / 替代解释未封堵 / 单点依赖

## ③ 投稿物料清单（以番茄为例）

| 物料 | 规格 | 生产方式 |
|---|---|---|
| 章节正文 | 每章纯文本 txt（标题单独填） | writer.db 导出（`data/writer/<书名>-全本.md` 为基准，勿用旧导出） |
| 简介 | ≤500 字，钩子前置 | 参考森铁版式：枕巾认亲（情感）＋核心悬念（物件）＋结局回收句＋"全文完结" |
| 封面 | 番茄 600×800px，jpg/png，<5MB，书名+笔名清晰 | Gemini 生成（opencli gemini image --timeout 480 --rt 3:4），**中文文字必须逐字验收**（错字/乱码/水印） |
| 笔名 | 平台间可不同 | 账号注册时定 |

封面生成命令模板：
```bash
opencli gemini image "<画面描述 + 文字排版要求（一字不差，禁其他文字水印）>" \
  --rt 3:4 --op <输出目录> --timeout 480
sips -z 800 600 <原图.png> --out cover-600x800.jpg \
  --setProperty format jpeg --setProperty formatOptions 92
```

## ④ 平台操作（人工执行，AI 只备料）

按 [[browser-ops-user-drives]] 惯例：开户、实名、上传、报名问卷一律作者亲手点击。AI 可代驾：文本/图片资产生产。

番茄「千字万金」要点（2026-08-28 核实）：第三期 06.21–09.30；中短篇 2.5-10 万字完结、推荐第三人称；保底 100-700+ 元/千字；分成 10:0；**每本书只能报名一次**，传完 15 章核对后再报；独家首发——报名后文字/音频不得再上任何外部平台。

## 修稿与回滚惯例（writer.db 是唯一真身）

- 修订一律走**新 chapter_revision**（source='correction'），不改旧版；回滚 = 把 `chapter.active_revision_id` 指回旧修订
- 动库前整库备份：`data/writer/writer.db.pre-<动作>-<日期>`
- 全本导出随时可重生成；旧导出会过期，**以 DB 为准**
- 双层标题导出 md（`## 第N章（字数）` + `# 第N章`）会被审计管线自动滤碎片并重编号，无需手工处理

## 附：本 SOP 的由来（一句话版）

盐选拒稿 → 诊断出评测错配（revision 权重淹没最低维）→ 建平台投稿门（本 SOP ①）→ 拒稿理由另一半"剧情逻辑" → 建推敲器（本 SOP ②）→ 47 处修订 + 6 轮复审零复发 → 番茄投稿物料齐 → 流程固化为本文档。
